# AUTOSAR R19-11 DLT v1 条款与验收矩阵

规范基准为 AUTOSAR FO R19-11，文档号 787。最终目标是覆盖该版本定义的 DLT v1 报文和可观察协议行为。矩阵按库、外部接收工具和 ECU DLT 模块分配条款，并为每段留出可执行的验收条件。规范中可能相互冲突的叙述单列，避免将外部实现习惯写成规范条文。[AUTOSAR 官方规范](https://www.autosar.org/fileadmin/standards/R19-11/FO/AUTOSAR_PRS_LogAndTraceProtocol.pdf)

矩阵覆盖第 5 章 161 个条款编号。状态字段描述复审阶段的证据。“已有”指有代码和对应样例，“部分”指已具备一部分行为，仍需完成或补测表中条件，“计划”指需交付。Legacy 入口用于接收现有文件或保存原始字节，R19 严格校验、标准输出和独立工具兼容性应分别报告。

## §5.1.3 标准参数

高级路径按结构和位宽解释载荷，支持编辑后重新生成记录。37→38 字节的是载荷长度，Storage 记录带头为 67→68 字节。数值和配置约束均受报文/树预算限制。[规范第 32–43 页](https://www.autosar.org/fileadmin/standards/R19-11/FO/AUTOSAR_PRS_LogAndTraceProtocol.pdf#page=32)

### 不同实现的对照范围

R19-11 将 Type Info 定义在 payload 中。MoonDLT 按 MSBF 读写整 32 位。固定的 Rust 对照版本 `dlt_parse 0.10.1` 通过固定位置的字节提取其中的标志，写入时固定编码字节；其 TRAI 写入路径只生成固定 SCOD。Rust 对照报告应标清共有用例，完整的大小端、SCOD 和不重合数组布局由规范向量独立判定。已有 pydlt 54＋192 条对照属于共同标量范围。[Rust 固定版本的 Type Info 解析](https://github.com/JulianSchmid/dlt-parse-rs/blob/v0.10.1/src/verbose/verbose_value.rs) · [TRAI 写入](https://github.com/JulianSchmid/dlt-parse-rs/blob/v0.10.1/src/verbose/values/trace_info_value.rs)

## §5.2–§5.3 数据与服务

数据消息遵循 §5.1。控制消息按扩展头的 MSTP/MTIN 分派，载荷由 32 位服务 ID 和服务参数组成。请求、响应、通知格式由协议库验收，配置作用和应用通知通过宿主测试替身验收。下表同时保留基线状况和各自完成条件。当前标准入口支持保留字节读写和 NOAR，控制测试检查新请求、GetLogInfo 状态 6/7、描述截断、同步时间、溢出计数及预检查状态。0x0A 默认按 00644 返回 NOT_SUPPORTED，宿主可以显式启用正式服务。[规范第 44–59 页](https://www.autosar.org/fileadmin/standards/R19-11/FO/AUTOSAR_PRS_LogAndTraceProtocol.pdf#page=44)

| 章节与条款 | ID 与功能 | 基线和验收条件 |
| --- | --- | --- |
| §5.3 00635、00187 | 全体 18 种命名服务 | 逐 ID 验证两种端序的标准请求、应答或通知、正确的控制消息头与长度。即使通用 envelope 能保留服务载荷，类型语义仍须按行核对。 |
| §5.3.1–.2 00194–00196 | 0x01 SetLogLevel、0x02 SetTraceStatus | 基线请求有类型。补齐空 APID/CTID 的择配，保留位忽略/输出零和默认值状态。宿主测试校验可观察的应用通知与应答。 |
| §5.3.3 00197 | 0x03 GetLogInfo | 基线有请求与通用响应。对 status 6/7 验证嵌套列表、可选描述、长度和完整消费；对 reserved 选项、未匹配、超长与 status 1/2/8/9 验证应答。status 7 表内明确要求 VERB=1，并列出相应列表格式，应由专门用例核对 Service ID 分派、分支长度及扩展头，不使用普通参数入口代替。 |
| §5.3.4 00198 | 0x04 GetDefaultLogLevel | 基线类型化请求和 level 响应。用标准级别与失败状态测试服务载荷。 |
| §5.3.5–.6 00199、00200 | 0x05 StoreConfiguration、0x06 ResetToFactoryDefault | 基线请求已读写。用注入的内存配置、持久化替身验证状态应答和失败。 |
| §5.3.7 00205 | 0x0A SetMessageFiltering | 实现请求位和应答格式。00635 将其列为正式服务，00644 同时列入 NOT_SUPPORTED。分别出具协议字段和宿主处置验证，保留歧义的条款依据。 |
| §5.3.8–.9 00380、00381、00383 | 0x11 SetDefaultLogLevel、0x12 SetDefaultTraceStatus | 基线有范围检查的类型化请求。验证保留字段、配置更新及返回状态。 |
| §5.3.10 00393 | 0x13 GetSoftwareVersion | 基线有请求与长度前缀响应。验证双端序字节长度、正文和不同状态。 |
| §5.3.11–.13 00494、00502、00638 | 0x15 GetDefaultTraceStatus、0x17 GetLogChannelNames、0x1F GetTraceStatus | 验收验证状态位、定长四字节通道数组、通道计数、APID/CTID 及未匹配应答。 |

## 初审与最终验收分别使用的证据

初审材料至少应给出结构体、TRAI、128 位的双端序实际结果，明确最终目标纳入所有标准参数与适用协议行为。使用 `python scripts/test_review_record.py` 复现真实文件解码、业务字段修改与独立预期字节核对。仓库 CI 启用 Rust 对照，已覆盖双方共同支持的小端 STRU/TRAI/U128/I128/FIXP/F16/F128。公开检查绑定具体提交。最终验收逐条补上适用角色、完整输入、精确结果、失败分支和证据链接，并为规范歧义保留可重复验证的选择依据。

§6.1 日志等级语义与 §6.2 长 ID 方式分别列为使用指导与条件扩展。使用长 ID 时再验证头部引导格式、解码引用位置和相应字符串参数。DLT v2 与其他版本的 ARXML、厂商自定义诊断程序和总线会话栈均有自身的协议或环境规范，R19-11 矩阵按本版本定义的 DLT 行为验收。[规范第 67 页](https://www.autosar.org/fileadmin/standards/R19-11/FO/AUTOSAR_PRS_LogAndTraceProtocol.pdf#page=67)
