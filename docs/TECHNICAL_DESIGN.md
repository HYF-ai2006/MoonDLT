# 技术设计

## 数据从哪里来，最终交给谁

消费者提供 `.dlt` 文件的字节片段，或接收端已经取得的 Network/Serial 字节。核心解析器只接收 `BytesView`，返回消息、消费字节数或带位置的错误；文件、网络、异步调度和硬件连接由宿主负责。输出仍是标准记录，因此能够交回已有 DLT 工具。

## 记录边界与类型边界分开

标准头的 16 位长度字段使用网络字节序。ECU、session、timestamp 等可选字段由头标志控制；其中数值头字段也使用网络字节序，载荷中的数值和类型词则服从 MSBF 标志。`.dlt` Storage 头自身使用固定的小端秒/微秒字段。这些字节序不能混为一谈。

解析先验证封装，再计算头部最小长度并核对整条记录的声明长度。所有切片在读取前检查边界；分配和缓存增长受 `Limits` 限制。得到记录后保留 `payload: Bytes`，消费者再主动调用 `arguments()`。这允许转交不理解的厂商载荷，同时避免把“成功识别头部”误写成“完整解码参数”。

## 增量状态机

`StreamDecoder` 保存未完成的尾部、输入/输出计数、恢复跳过计数及开闭/失败状态。每次 `feed` 处理当前能够形成完整记录的输入，剩余尾部等待下一次。调用者必须按缓存预算提供块大小，不把整份大文件一次塞入固定预算。

严格模式遇到损坏或不支持的封装立即失败。失败后必须显式 `reset`，避免把同一次输入只交付一部分结果却暗示全部成功。`finish` 检查是否仍存在残缺记录，不能悄悄吞掉截断尾部。

恢复模式只适用于带魔数的 Storage/Serial，保留跨分片魔数前缀，逐字节寻找下一个可信记录候选并核对头和长度。扫描有独立上限，跳过字节对外可见。Network 没有唯一魔数，因而拒绝自动恢复。恢复只能帮助继续查看损坏后的记录，不能证明此前数据完整。

## 参数、字典与范围

常用 verbose 参数以代数数据类型表达，保留位宽与文本编码，64 位整数不先转换为浮点数。字符串按声明的编码和终止规则处理；参数数目、类型位与剩余字节都需要匹配。高级类型若不受当前 API 支持，解码应拒绝猜测后续参数边界。

nonverbose 消息只包含消息 ID 和应用自定义字节，不可能仅凭字节可靠推断其结构。应用可注册 `(application, context, message_id)` 对应的固定布局，字段携带名称、类型与单位；解码检查总长度。这是显式 schema API，不是 FIBEX XML 解析器，也不声称能自动解码任意厂商日志。

高级参数使用独立的 `VerboseParameter` 模型：可选变量名称和单位、整数固定点描述、同类数值数组的维度与平铺值均显式保留。简单 `arguments()` 不猜测高级类型，消费者需要选择 `parameters()`。维度乘积先按消息预算检查，避免先乘法溢出或分配后再拒绝。高级 API 的标准审查和单元测试独立于只覆盖常用标量的 pydlt 互操作。

JSON 交换也不依赖宿主 Number 表达所有值：64 位整数采用规范十进制字符串，浮点采用 IEEE 位模式，文本保留编码，raw 保留十六进制。这样跨 Wasm/JS 的宿主工具可以往返数据而不因 JSON 数字精度发生静默变化。

## 索引与过滤如何保持可复用

索引项保存原始输入的字节偏移、记录长度和头信息。过滤按 ECU、应用、上下文、消息类型、等级、存储时间进行匹配；没有提出时间条件时可处理缺失 Storage 头的消息。时间使用整数微秒，ECU uptime 不被误当成 UTC。

提取时复查索引区间与实际记录，复制选中记录的原始字节；需要转换封装或参数时则走显式重新编码。这样消费者可以实现日志子集导出与容器转换，而不必依赖固定业务表结构或报告模板。

`Source` 为大文件提供 UInt64 偏移和精确读取回调。`SourceCursor` 只读封装与头信息并跳过载荷，选择记录后才读取该条；完整 payload 语义验证需要显式 verifier。窗口缓存持有一个有界区域。回调必须保证输入在扫描和提取间不变，库不承诺文件系统事务或检测一切中途修改。

`SourceCatalog` 可将元数据目录写为 JSON 侧文件，解析时检查完整连续覆盖、字段类型、头部合法性和条目预算。默认 `open` 先对源采样标识，再用 `SourceCursor` 逐条重新核对所有元数据，核对完成后才允许依赖目录查询。每条选中记录读取时再次核对。显式 `open_trusted` 为调用者已验证并控制的目录提供快速路径，只检查采样标识；其名称表示信任责任，不表示获得认证。采样使用非密码学散列，不能阻止有意构造冲突或检测未采样载荷变化。

头字段表达式单独设置输入字节、token、深度和节点预算，支持比较、布尔组合与括号。字段值缺失使比较为 false，包括 `!=`，外层 `!` 再做否定。它只观察头字段，不作为通用脚本语言，也不隐式解析载荷。

控制模块只负责常用请求/响应字节，不发送命令。连续性模块报告观察到的计数器重复、跳变、时间戳回绕或倒退；应用重启、捕获范围变化也可能产生这些现象，因此不能把事件数量自动解释为实际丢包。

## 复杂度与已知约束

基础编解码按消息字节数线性工作；当前分片处理会复制 pending 和新块，最高缓存受预算约束，不宣称零拷贝。字典以有界线性表注册和查找，适合小型应用字典，不适合数百万消息模板。索引占用与记录数成正比；超大文件应在宿主层逐块处理，不能把内存索引称为磁盘数据库。

跨目标兼容由统一字节实现与各目标测试验证，而非通过 FFI 调用一个原生库后声称“MoonBit 实现”。性能数字只有在固定工作量、目标、工具链和机器上实测后才可公布。
